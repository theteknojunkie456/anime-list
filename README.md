# WatchList

A personal anime / manga / show / movie tracker that runs entirely in the browser — no accounts, no database. Installable as an app on your phone (PWA) and hosted free on GitHub Pages. Tracks both what you **watch** and what you **read** (manhwa, webtoons, light novels), with real cover art, airing schedules, and episode notifications.

**App:** https://theteknojunkie456.github.io/anime-list
**Friends (shareable) viewer:** https://theteknojunkie456.github.io/anime-list/friends.html — see [FRIENDS.md](FRIENDS.md)

## Install it

- **Android** — [android.html](https://theteknojunkie456.github.io/anime-list/android.html): install from Chrome in two taps, or download the signed **APK** from [Releases](https://github.com/theteknojunkie456/anime-list/releases/latest). Verified against the site with Digital Asset Links, so the app runs without a browser address bar. See [ANDROID.md](ANDROID.md).
- **iPhone / iPad** — open in Safari → Share → **Add to Home Screen**. For screen-sharing a party, the native app in [ios-broadcast/](ios-broadcast) is the only thing on iOS that can capture a screen.
- **Desktop** — it just runs; Chrome will offer to install it.

All of them load the same live site, so a deploy reaches every surface at once. Only the native shells need rebuilding, and only for icon/name/native-capability changes.

## Two versions, one app

| File | Who it's for | Storage key |
|------|-------------|-------------|
| `index.html` | The main app — everyone starts with their own **empty** list | `animelist_v4` |
| `friends.html` | A viewer for a friend's shared list, so browsing theirs never touches yours | `animelist_friends_v4` |

Both files are the same app; they differ only by that storage key. New users start **blank** — no demo seed to delete. The tutorial (which opens immediately on a fresh install) explains what the app does, and the empty state offers *Add a title* or *Import a list*.

Every list is saved in **your own browser** (localStorage) and, optionally, in a private cloud store gated by a secret sync code — nobody can see anyone else's data, and the two versions use separate storage so they never mix. See **[FRIENDS.md](FRIENDS.md)** for how sharing works.

> **Privacy:** the repo is public (that's just the app code), but no personal list is in it — `index.html` ships an empty list; your real titles stay in localStorage and, if you enable sync, in a private code-gated cloud copy.

## Features

- **Watch _and_ Read** — a Watch/Read toggle splits the app into two lists: anime/TV/movies, and manga/manhwa/webtoons/light novels. Each entry has statuses: Plan · Watching/Reading · Done · Dropped.
- **Real cover art (incl. manhwa/webtoons)** — every entry shows its real poster, fetched automatically in the background and captured during autofill from:
  - [AniList](https://anilist.co) — anime **and** manga/manhwa/webtoons/light novels (via `type: MANGA`), plus a per-title dominant color and wide banner art
  - [Jikan](https://jikan.moe) (MyAnimeList) — anime franchise relation graph for watch order
  - [TVMaze](https://www.tvmaze.com/api) — live-action TV, per-season breakdown
  - [Open Library](https://openlibrary.org/developers/api) — books
  You can also **upload your own** cover, and a wrong auto-match can be removed in Edit.
- **Autofill** — type a title and pick from real matches: the app searches **AniList** (anime for your watch list, manga/manhwa/webtoons for your reading list) and offers a short, **grouped** shortlist — an **Anime** section (top ~3) and a **Live action** section (top ~2) with a header on each — instead of a flat wall of results, each labelled with year/network/episode count. Choosing one fills in episodes/chapters, hours, genres, notes and cover. It deliberately **asks instead of guessing** — one title can mean several things ("One Piece" is a 1999 anime, a 2027 remake, films, and a Netflix live-action), and the old behaviour of taking the first hit from whichever API answered first meant a MyAnimeList outage silently filled in the wrong show. Watch order (series chain + franchise movies, side OVAs, recaps marked SKIP) still comes from MyAnimeList's relation graph, but only as best-effort enrichment *after* you've chosen — a missing watch order beats a wrong title. Free public databases, no key needed.
- **Watch now (anime, in-app)** — a logged **anime** (not manga, not live-action) gets a **Watch** button that plays it *inside the app*: a pristine full-screen player (back · title · video, nothing else). It deep-links to your **next unwatched episode** (clamped so it never 404s past the finale). The frame is **sandboxed** — no `allow-popups` / `allow-top-navigation` — so the streaming site can't spawn pop-up ad tabs or redirect the app away, while the video still plays. **Your source:** Sources lets anyone point Watch at the site they already use. **One-tap presets** (HiAnime · AniWatch · GogoAnime) open that site's search for the exact title; or type any site — a **bare domain** like `hianime.to` works (https:// is added for you), and a URL can use `{title}` / `{slug}` / `{ep}` tokens (e.g. `https://site.com/watch/{slug}/ep-{ep}`). Note only sites that allow iframe embedding *and* play in-frame work — DRM services (Crunchyroll, Netflix) and framing-blocked sites (mangadex, comick) can't be embedded. Default subs are **soft** (separate subtitle CDN); dub/sub and server switching are the streaming site's own on-page controls (can't be injected — cross-origin). **Real-slug resolution (no more 404s):** sites slug titles their own way — romaji, punctuation dropped ("Re:Zero" becomes `rezero`, not `re-zero`) — so a title-derived guess often missed and 404'd. The browser can't read the site's search (no CORS), so the **Worker fetches it server-side** and returns the real `/watch/<slug>` candidates; the app picks the one whose canonical title matches this exact item — **season markers normalized** ("Season 2" ≡ "2nd Season" ≡ "II") and required to match, so it never plays the wrong season — then deep-links straight to it. The resolved slug is cached on the item, so it's instant next time. **404 recovery (fallback):** when no candidate is a confident match (e.g. a split "Final Season"), or the app is offline, the player's **search button loads the site's results for that exact title in-frame** — one tap, no typing, no leaving the app, for both watch and read. **Survives an app reload:** iOS purges an installed PWA when you background it (Home screen / exit fullscreen), which otherwise reloads the app and loses the player. The active session is stashed, so on the next load — right after unlocking, if a password is set — the player **re-opens automatically to the same episode** (within ~6h; an intentional close doesn't spring back). The exact second is the streaming site's own resume, but landing back on the same episode is what lets that kick in.
- **Your own site, in one paste** — setting up a streaming source used to mean three separate fields for the same link and an AI key demanded halfway through. Now: open **Sources**, start any episode on your site, and paste that page's address. WatchList reads which show and episode it is, tells you so in plain words, proves it generalises by resolving a *different* show from your list, and one button sets it for everything. No key — the AI is a fallback that only appears if the link genuinely can't be read, and it remembers what you pasted so going to fetch a key doesn't cost you the link.
- **Set the right one** — sites disagree about what a show is called (*Initial D* on one is `initial-d-first-stage` on another), so a deep link can land on that site's 404. The player offers **Try another spelling** (cycles the title variants), **Search this title**, and **Set the right one**. Searching opens the site's results in the frame and the set panel with it, so you read what the site calls the show and just type that — no copying a URL out of an iframe on a phone. Pasting the address still works and additionally learns the site's URL shape. Either way WatchList learns what *that site* calls that show, permanently. Learned names are keyed by site, so they apply to shows you haven't added yet and never leak onto a different site. One builder now produces every episode link, so a correction also fixes Next, Prev and *Mark watched & next* — which previously built their own URL from the title and 404'd on shows you'd just fixed.
- **Share your whole setup** — **Sources → Share mine** produces a link anyone can open. They see in plain words what they're getting, tap **Accept**, and receive your site, the sites you added, the links you taught it, and **every show you corrected by hand** — so shows that never worked for them simply work. It never touches your own settings, adds to theirs rather than replacing, and needs no friend request.
- **Only the sites I added** — one switch hides every built-in suggestion, including ones added in future updates, instead of hiding fifty things by hand. Individual hides are remembered underneath, so switching it off restores exactly what you had. And a hidden source is now hidden *everywhere* — including the free fallback Watch uses, which previously ignored the hidden list and sent you to a site you'd explicitly removed.
- **Every episode, with art** — open any show and you get all of its episodes, numbered, each with artwork: the official still where one exists, the show's own cover dimmed with the number over it everywhere else. Watched ones dim, the next is lit. It no longer depends on a third party having published per-episode links.
- **Finish a season, get the next** — mark a season **Done** and if there's a next one, WatchList offers it: one tap to add it and carry on. Asked once, never nagged — a "not now" is remembered per show, and a sequel already on your list is never offered.
- **Take back a recommendation** — sent something to a friend by mistake? **Friends** lists what you've recommended and to whom; **Take back** removes it from their app. It disappears the next time they open WatchList (if they've already read it, that can't be undone).
- **Adult titles stay out** — filtered on every path that returns titles, including the ones that previously had no filter at all: the franchise/seasons walk (which follows side stories and spin-offs, exactly where adult versions of ordinary series hang off), the next-season offer, and *More like this*.
- **Read now (manga/manhwa/webtoons)** — a logged **reading** item gets a **Read now** button that opens **AsuraScans** (default) in the same in-app frame. It deep-links straight to the series (`/comics/<slug>-<suffix>`, where the suffix is a constant site-wide token, `ASURA_SUFFIX` in `index.html`). Swappable in Settings → *Watch & read sources* with an optional `{title}`/`{slug}` token.
- **Progress saving after watching** — we can't see inside the cross-origin player to auto-detect what you watched, so when you leave the player a quiet snackbar asks: *"Watched Ep 12? — Mark watched"*. One tap advances your progress (saved to localStorage + cloud sync). **Time-based auto-mark:** stay in the player ~15+ min (a full episode) and it marks the episode watched automatically on exit, with an **Undo**; under 2 min it assumes you only peeked and does nothing; in between it asks. It's a heuristic (we can't read the cross-origin player) — the Undo covers the rare miss.
- **In-player binge controls** — a logged anime's player shows **◀ Prev · Mark watched & next · Next ▶** along the bottom. Step episodes without leaving the player, or tap *Mark watched & next* to bank the current episode (progress saved) and jump straight to the following one — binge without bouncing back to the list. On the finale it becomes *Mark finished* and closes out. Shown only when the source can address a specific episode (any source with an `{ep}` token); hidden for search/plain sources and for reading.
- **Continue watching** — a home rail of your in-progress anime, each card jumping **straight into its next episode's player** (skipping the detail page). Presented as its own band — framed by a hairline top and bottom — of **uniform cinematic 16:9 cards** with the cover art, a bottom scrim, the title and next-episode number overlaid, a progress bar, and **one consistent glassy play button** on every card (no per-cover colour clash). The row **loops infinitely** — scroll sideways forever, it never dead-ends or snaps back. Watch-list only (needs an episode deep-link).
- **Pick one for me** — the decide-for-me button riffles through your list, lands on one, and says *why*: "You're 8 of 12 in — 4 left", or "Rated 8.4 on AniList, and only 12 episodes." It ranks on AniList's community score first, then on what you can realistically finish and what you've already started — it isn't a coin flip with an animation on top. **Anything · Short · Almost done · Not started** live inside the picker, so you can change your mind without going back. Reduced-motion gets the answer immediately.
- **Community score, stored** — every title now carries AniList's score. It weighs on what gets picked, shows on the pick card, and adds a **Top rated** sort (your own stars are **Your rating**, since there are two). It's refreshed on the same pass that fetches covers, and backfilled for everything already on your list.
- **Sites that won't embed are remembered** — a site refusing to be framed looks exactly like one still loading, and cross-origin rules mean the app can't ask. So it learns per host: reaching for *Open in browser* while the blank panel is up counts as a failure, a session past 20 seconds that never needed it counts as a success. Two failures with nothing on the other side and that host skips the player instead of showing you a blank rectangle for eight seconds. One session that works clears the record.
- **Colour conditioning** — per-title accents are drawn from each cover's dominant colour, but raw art colours run from washed-out pastels to muddy greys that look bad as UI. Every one is now pinned into a vivid, dark-theme-friendly band (its hue kept, saturation and lightness clamped), so accents always look deliberate — Naruto stays orange, but a pale-pink cover becomes a rich rose instead of a muddy wash. Applies everywhere a title tints the UI (spotlight, detail, ambient glow).
- **Infinite spotlight** — the home billboard carousel loops seamlessly: swiping forward past the last slide continues into the first instead of sweeping all the way back, via cloned edge slides that snap invisibly at the seam.
- **Weekly schedule** — a calendar of everything you're tracking, week by week (prev / next / "this week"), each day listing what lands and when in your local time. It shows **both sides at once** regardless of which list you're viewing: episodes come from AniList airing data (delay-aware, with an offline fallback), and reading comes from each series' own release rhythm. Nothing publishes a manga chapter date the way AniList publishes an episode time, so those entries are **projected** from real dated releases and their median gap, drawn a step quieter and labelled *expected* — a scanlation slipping a week is normal, not a broken promise. A series whose last release is older than four of its own cycles is treated as stalled and left off rather than given a schedule it no longer keeps.
- **For You (recommendations)** — tailored picks *not on your list yet*, from AniList's community recommendation graph (real titles, not AI-generated). It follows the side you're on: browsing **Watching** recommends shows, browsing **Reading** recommends manga, manhwa and webtoons, each from that list's own history and cached separately. Recommendations are type-checked, so a manga's anime adaptation never turns up as a reading pick. Aggregated across your list (weighted Finished > Watching > Plan) with a "Because you read/watched X" reason and one-tap **+ Plan**, which adds to the list it came from.
- **All seasons under one title** — a title's detail page lists the **whole franchise**, every season, not just the ones on your list. Seasons are gathered from **two independent sources merged** — AniList's sequel/prequel relation graph *and* MyAnimeList (Jikan), each walked hop-by-hop — so a gap in one can't hide a season: this catches arc-named seasons (*Demon Slayer*'s Mugen Train / Entertainment District / Swordsmith Village / Hashira Training), differently-titled ones (*Attack on Titan*'s "Final Season", *Mob Psycho 100 II/III*), and even just-announced seasons one source hasn't populated yet (*Konosuba* S4). Each season row shows its status/progress if it's on your list, its air date if upcoming, and a **watched** check; ticking one adds it as a finished entry. **Seen all** marks the entire franchise watched in one tap. On the home screen these collapse into a single card (with a "N seasons" pill) so they never clutter your rows.
- **Airing times** — watch anime show their next-episode air time (local, delay-aware) on cards and detail. The date is **confirmed against AniList's actual next-episode schedule for that exact season** (refreshed by its AniList id, never a title-search guess that could drift to a different, currently-airing season). Episodes within a week show the weekday + time ("Wed 4:00 PM"); anything further out shows the real date ("Aug 12"), so a premiere months away never reads as *this* Wednesday.
- **Episode notifications** — opt in and get a push when a new episode of a show you're Watching/Planning actually airs, at the real air time. Backed by a Cloudflare Worker (cron every 15 min + Web Push). On iPhone, add the app to your Home Screen first (iOS 16.4+). See [cloud/](cloud).
  Because the worker only announces episodes that aired in the last 40 minutes, a list of mostly *finished* series can legitimately stay silent for weeks — which reads as "broken" when it isn't. So Settings → Notifications **says what it's doing**: how many shows are tracked and what's next (*"Next up: BLACK TORCH Ep 3 — Saturday 9:00 AM (in 3 days)"*), or plainly that nothing's airing soon and the quiet is expected. **Send a test notification** proves the whole chain — VAPID signing → Apple/Google push → service worker → lock screen — in two seconds instead of waiting for an episode; if your push endpoint has died (every Home Screen reinstall mints a new one) it detects that and re-subscribes.
- **Cinematic title page** — tapping any title opens a full-screen, streaming-style page (not a popup): a large banner-art hero that parallaxes and fades as you scroll, the title floating over it, and everything — progress, rating, status, watch order, notes — flowing below. Slides up; back button to exit.
- **Per-title theming** — each title's detail/hero uses its real **banner art** as a background (with a legibility scrim) and tints its accent from the cover's dominant color — automatically. You can also set your **own background photo** per title (auto-compressed).
- **Themes** — character-inspired colour themes plus a custom builder. **Harmonize** takes the two colours you picked and turns them into a palette that works: it reads which classical scheme you were reaching for from the gap between them (analogous, triadic, split-complementary, or the tetradic rectangle) and snaps to that exact geometry; assigns roles by 60/30/10; gives the ambient glow the *partner* hue so a theme stops reading as one colour smeared over a page; and names the result. Built in Oklab/OKLCH rather than HSL — at the same HSL lightness a yellow is roughly three times as bright as a blue, so any rule written in HSL treats half the wheel unfairly. Contrast is measured with **APCA** (the WCAG ratio badly misjudges light-on-dark, i.e. this app), out-of-gamut colours are mapped per CSS Color 4, and the accent/glow pair is checked under simulated protanopia and deuteranopia — a textbook complement can still collapse into one colour for roughly one man in twelve. Every theme — including ones you build — is **WCAG AA** by construction: the three text tiers are lifted until they clear 4.5:1 against that theme's own surfaces, and each accent gets the foreground that actually contrasts with it (near-black on Naruto's orange, white on Sasuke's purple) rather than assuming white.
- **Responsive** — auto-adapts between portrait and landscape (and tablets/wide screens): a widescreen hero, fluid poster grids, and modal sheets in landscape.
- **No duplicates** — adding a title you already have opens the existing entry instead of creating a second copy. Matching ignores case, spacing and punctuation; your watch and reading lists are separate namespaces, so the anime and the manga of the same name can both live in your library.
- **Import from AniList / MyAnimeList** — paste your username and pull your whole list in one shot: titles, status, episode/chapter progress, ratings, covers and AniList IDs, for both anime and manga. AniList is a reliable GraphQL call; MAL goes through Jikan (best-effort). The list must be public.
- **Watch parties** — watch together with friends over a short shareable **room code** (the people icon in the header). Start a party, share the code, friends join; you get **live presence** (who's here) and a **live chat** (“yo pause a sec, brb”). Two ways to watch together:
  - **Screen share (true sync, free).** A host on a **computer** shares the tab they're watching in, and everyone — phones included — watches the host's actual screen over **WebRTC, peer-to-peer**. Play, pause, seek, skip: all perfectly synced automatically, because it's literally the host's pixels. No server carries the video (device-to-device), so it costs nothing; the only server bit is tiny offer/answer signaling on the worker. Late joiners connect to the live stream automatically. *Only the host device must be a desktop* — Apple blocks screen capture in iOS browsers, so an iPhone can't host (but can watch fine). Best for a handful of viewers; a large mesh is limited by the host's upload.
  - **Host runs the session (loose sync, any device).** The host picks the anime + episode from a scannable list and hits **Play together** → a synchronized **3·2·1 countdown**, then every player opens to the same episode at once. From there the host is the **remote for the whole party**: **Pause everyone** drops a "Host paused" veil over every viewer's player; **Resume** re-aligns them with another 3·2·1; **Next episode** makes everyone auto-jump to the next one. Not frame-synced to the second (the embed is a cross-origin frame we can't literally drive — the pause is a veil, not a hardware pause), but it's a real "everyone follows the host" session that works with everyone on iPhones, and friends who don't even have the show still watch along.
  - **Synced playback (the good one).** For anything WatchList plays itself, the host's player drives everyone else's: **pause, play and seek all follow**, so only the host is hands-on. Everyone keeps full quality, their own audio and their own subtitles, nothing is uploaded, and it works on devices that can never capture a screen — because these are commands, not video. The host reports position every 2.5s and instantly on pause/resume; viewers only correct past 1.5s of drift and compensate for the network hop. **Re-sync** restarts the countdown on whatever is playing, to line a drifted party back up.
  - **Voice and video** — WatchList draws the call itself rather than embedding someone else's, so every person gets their own tile with a soft border in **their own colour** that lifts into a glow while they're speaking. Mic, camera, screen share, grid/speaker and full screen all live in WatchList's own bar. **Mirror** flips your camera for everyone, not just your own preview — one property broadcast, no re-encoding. If any of it can't start on a device, the call quietly falls back to the embedded one: a nicer-looking call is never a reason for no call.
  - **Live emoji reactions** — tap a reaction and it floats up over everyone's screen in real time.
  **Where screen sharing actually works:** a computer can share its screen from the call. An iPhone cannot from *any* web page — WebKit has no `getDisplayMedia`, so neither Safari, nor an installed PWA, nor an embedded Jitsi can capture, and no embed can add a capability the engine lacks. On iPhone the routes are the **app's Broadcast your screen** (ReplayKit, whole screen with audio) or the synced playback above, which is better for video anyway: a shared screen is a re-encoded, compressed copy that DRM'd players render black. The [Safari extension](ios-safari-ext/) adds real play/pause/seek sync on third-party sites from an iPhone.
  A floating pill keeps the party a tap away, and it survives an app reload (auto-rejoin, with automatic reconnect if the socket drops). **Real-time backend:** each room is a **Durable Object** the members connect to over a **WebSocket** — state is pushed the instant anything changes (a join, a chat, a control, a reaction), so presence is exact and there's no polling lag or stale-cache "they can't see me" (the earlier KV-polling design's flaw). Presence is literally who's connected; host duties hand off automatically if the host's socket closes. SQLite-backed Durable Object → free tier.
- **AniList two-way sync** — connect your AniList account (Settings → *AniList sync*) and the app becomes the hub: marking an episode, changing status, or rating here **pushes to AniList automatically** (from the player, binge controls, and detail view), and *Sync now* / a throttled background sync **pull** the latest back. Reconciles by the **higher** progress count so nothing ever goes backwards; local-only titles get created on AniList, and if it can't read your list it does nothing rather than overwrite. Any streaming site you've linked to the same AniList account then converges too — one shared number per show. Pure client-side: AniList's OAuth *implicit grant* needs no server or secret, and its GraphQL allows browser calls, so this stays a static app. Setup is one-time and self-serve — create a free API client at *anilist.co → Settings → Developer* (the sheet shows the exact redirect URL) and paste the **Client ID** (not a secret); it's stored only on your device, and each person/fork uses their own. Only titles with an AniList id sync (manual/live-action entries don't). *iOS note:* OAuth may open in Safari rather than the installed PWA, so the first connect is most reliable in Safari on the site.
- **Behind-nudge** — a gentle home banner for the currently-airing show you're most behind on (*"Dandadan — 5 new episodes since you last watched"*) with a one-tap **Resume** into the next episode. Shown only when the backup warning isn't (one banner at a time).
- **Import** — paste a plain-text list (one title per line, optional `- watching` / `- finished` tags) and bulk-import with a preview.
- **AI chat (optional)** — a real conversational AI companion that knows your list: streaming replies, markdown, chat history that persists, a model picker, and quick prompts tuned to your list (plus one-shot Suggest & Rank helpers). Paste a **free** key from [Groq](https://console.groq.com), [Google AI Studio](https://aistudio.google.com), or [OpenRouter](https://openrouter.ai) (or paid Claude). Auto-detects the provider; key stored only on your device. Everything else works without one.
- **Local resilience (never silently lose the list)** — every save mirrors a **last-known-good backup** alongside the primary copy, so if the primary ever reads back corrupt, the app **auto-recovers from the mirror** on next launch (and preserves the unreadable bytes to a `_corrupt` key rather than discarding them). Loading is defensive: a malformed or truncated entry is dropped and every item is guaranteed an `id`/`title`/`status`, so one bad record can't crash the list; each home section renders independently, so a thrown error degrades that section instead of white-screening the app. And a save can **never overwrite your encrypted list while it's locked** — a hard guard against the worst-case wipe. (Cloud backup via sync code is still the cross-device restore; this is the on-device safety net.)
- **Password lock (end-to-end encryption + recovery key)** — optionally set a password that encrypts your **entire list** with AES-GCM. Under the hood the list is sealed with a random **master key**, which is then wrapped twice — once by your password, once by a one-time **recovery key** — so *either* can unlock it (both via PBKDF2, 150k iterations). The list is stored as ciphertext on your device **and** in the cloud sync copy — genuinely unreadable without a secret, even in browser devtools. On launch the app shows a lock screen. **Forgot your password?** Tap "Use recovery key" and paste the code you saved at setup (accepts any spacing/case) to get back in and set a new one. Set / change / remove the password and re-issue a recovery key in Settings → Password. **Face ID / Touch ID unlock** (iOS 18.4+): a passkey's WebAuthn **PRF** extension derives a stable secret, and the master key is wrapped a third time with it — so biometric unlock is real cryptography, not a key left in localStorage behind a check. Password and recovery key keep working; the option is hidden where the platform can't do it. It stays **zero-knowledge** — no server, no account, no backdoor — so if you lose *both* the password and the recovery key, the data cannot be recovered. (A friend viewing an encrypted list via `friends.html` must be given the password.)
- **Typography & colour** — titles are set in **Bricolage Grotesque**, body in **Manrope** (deliberately not Inter, which every AI-generated UI converges on). Text runs on a three-tier ramp that is WCAG AA on every surface *and* keeps ~1.75× lightness between tiers, so "muted" still reads as muted instead of collapsing into the tier above. The accent marks primary actions and warnings only; section headers and settings rows wear the status palette (amber/blue/green/grey) so a theme tints the app without flattening it to one hue.
- **Tutorial** — a short "How it works" guide that **opens on the first frame** for a genuinely new install — before any content, no delay, no slide-in — and is never shown to anyone with an existing list. Reachable any time from Settings → *How WatchList works* (the first row). Eight steps, with **"Back up your list — do this first"** deliberately second, on the opening screen: it's the only step whose absence costs someone their entire list. It walks through adding titles, the Watch/Read switch, the schedule and notifications, and recommendations — and deliberately front-loads the thing that actually loses people their data: **turn on cloud backup and save your sync code**, plus how the password and recovery key relate.
- **Cloud sync + Friends** — sync your list across devices with a secret code, and share it read-only with friends. See [FRIENDS.md](FRIENDS.md).
- **Works offline** — service worker caches the app.

## Project structure

```
anime-list/
├── index.html            # The app (all CSS/JS inline, no build step)
├── friends.html          # Read-only friend-list viewer (blank start, separate storage)
├── manifest.json         # PWA manifest
├── sw.js                 # Service worker — offline cache + Web Push handlers
├── icons/                # App icons (icon.svg master + 192/512 PNG)
├── cloud/
│   ├── sync-worker.js    # Cloudflare Worker — list sync (pull/push by secret code)
│   ├── notify-worker.js  # Cloudflare Worker — episode push notifications (cron + Web Push)
```

## Development

Two agent skills are installed **project-locally** (`.claude/skills/`, gitignored — see the deploy note below):

| Skill | What it does |
|-------|--------------|
| [impeccable](https://github.com/pbakaus/impeccable) | Design guidance + a deterministic detector. A `PostToolUse` hook scans UI edits and flags AI-generated-design tells, contrast failures, and readability problems. `npx impeccable detect index.html` for a full pass. |
| [find-skills](https://github.com/vercel-labs/skills) | Discovers and installs other agent skills from the open ecosystem. |

> **Why gitignored:** the Pages workflow uploads `path: .` — the *entire repo* — so anything tracked is published to the live site. Local tooling (and `skills-lock.json`, and `.look-backup/`) stays out of git so it never ships.

Design tags mark restore points before visual overhauls: `look-v1` (pre-typography), `look-v2` (pre-prose-pass). Restore with `git checkout <tag> -- index.html friends.html`.

## Deploying changes

1. Edit and push to `main` → GitHub Actions deploys to Pages (live in ~a minute).
2. The **workers** (`cloud/`) deploy separately to Cloudflare. Notifications need `wrangler deploy` + a `VAPID_PRIVATE_KEY` secret + a KV namespace (see `cloud/wrangler.toml`).
3. The app fetches fresh files whenever online, so updates appear on next launch.

## Adding it to your phone

Open the link in Safari (iPhone) or Chrome (Android) → Share → **Add to Home Screen** — launches full-screen like a native app. (Required on iPhone for episode notifications, iOS 16.4+.)
